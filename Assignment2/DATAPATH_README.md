The existing Part A BDF entities are instantiated directly. Their internals,

## Main data paths

| BUS_SEL | Source |
| --- | --- |
| 000 | Constant zero (unused source slot) |
| 001 | AR, zero-extended from 12 to 16 bits |
| 010 | PC, zero-extended from 12 to 16 bits |
| 011 | DR |
| 100 | AC |
| 101 | IR |
| 110 | TR |
| 111 | Memory read output |

The common BUS feeds AR/PC through its low 12 bits, DR/IR/TR through all
16 bits, OUTR through its low 8 bits, and the memory write-data port through
all 16 bits. AC loads the ALU result rather than loading the common BUS
directly; a BUS value can reach AC by first loading DR and selecting ALU's
DR transfer operation.

AR supplies the 12-bit memory address. INPR loads INPUT_DATA and supplies
the ALU independently of the common BUS. OUTR drives OUTPUT_DATA.
All stored registers and flags use the same rising-edge CLK.

This matches the common-bus organization on PDF page 16 of
`Basic Computer Organization and Design Part2_Notes.pdf`.

## New components

- `alu16.bdf` contains sixteen `alu_slice.bdf` instances. Each slice has a
  gate-level full adder, AND/complement logic, seven operation-enable AND
  gates, and an OR combiner, following the annotated Part 3 ALU notes.
- `state_bit.bdf` implements a synchronous CLR > LD > hold flip-flop.
  It is instantiated for E, I, R, IEN, FGI, FGO, and the optional S bit.
- `extend_next.bdf` selects ADD carry, the shifted-out AC bit, complemented E,
  or held E. `FLAG_LD[0]` enables capture into E.
- `zext12.bdf` and `zero16.bdf` explicitly implement BUS width adaptation
  and the unused source's constant zero value.
- `memory4096x16.vhd` implements the RAM block shown on the schematic:
  4096 words of 16 bits, synchronous writes, combinational reads. READ_EN=0
  drives its output to zero. RAM contents are unspecified until initialized
  or written; no program image is assumed. This is a RAM model rather than
  a drawn bank of 65,536 flip-flops. It has not been fitted or tested on a board.

The added BDF modules and memory have BSF symbols. ALU and status logic can
be descended into or opened directly in Quartus. Memory opens as VHDL source.

## External control interface

The controller is the next design stage. These inputs allow all required
data transfers without embedding an instruction sequencer in this assignment.

| Input | Bit mapping / behavior |
| --- | --- |
| BUS_SEL[2..0] | BUS table above |
| REG_LD[7..0] | 0 AR, 1 PC, 2 DR, 3 AC, 4 IR, 5 TR, 6 INPR, 7 OUTR |
| REG_CLR[4..0] | 0 AR, 1 PC, 2 DR, 3 AC, 4 TR |
| REG_INC[4..0] | Same mapping as REG_CLR |
| ALU_OP[6..0] | One-hot: 0 AND, 1 ADD, 2 DR, 3 INPR, 4 COM, 5 SHR, 6 SHL |
| MEM_READ_EN | Enable combinational memory output |
| MEM_WRITE_EN | Write BUS data at the rising CLK edge |
| FLAG_LD[6..0] | 0 E, 1 I, 2 R, 3 IEN, 4 FGI, 5 FGO, 6 S |
| FLAG_CLR[6..0] | Same mapping as FLAG_LD; clear overrides load |
| FLAG_DIN[4..0] | 0 R, 1 IEN, 2 FGI, 3 FGO, 4 S |
| E_COM | Select NOT E as E's next value; also assert FLAG_LD[0] |

ALU_OP is a set of seven operation enables, not a binary operation number.
Assert at most one bit. All-zero ALU_OP produces a zero result. INPR transfer
sets AC[15..8] to zero. SHR/SHL rotate the 17-bit E:AC pair when both AC and E
loads are asserted. For ADD, assert AC load and E load to capture sum and carry.
Do not assert AC's increment simultaneously when expecting an ALU load:
the reused counter's priority remains CLR > LD > INC.

I's data input is IR[15]. R=0 represents an instruction routine and R=1 an
interrupt routine. IEN enables interrupts; FGI/FGO carry input/output-ready
state, and S carries the run state. Flag-setting and routine timing are
provided by the external controller; this sheet does not include instruction
decoding, a sequence counter, interrupt recognition timing, or an I/O device.
FLAG_Q exports all seven bits to that future controller.
